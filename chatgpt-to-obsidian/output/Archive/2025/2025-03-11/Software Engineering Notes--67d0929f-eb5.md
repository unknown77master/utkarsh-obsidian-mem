### **Q3 (a) List all the tasks in requirement engineering. Explain it in brief.** 
#### **Requirement Engineering Tasks:**
Requirement engineering is the process of gathering, documenting, and maintaining system requirements. It involves the following tasks: 

1. **Requirement Elicitation** 
 - Identifying stakeholders. 
 - Collecting requirements through surveys, interviews, and brainstorming. 

2. **Requirement Analysis** 
 - Evaluating gathered requirements. 
 - Identifying conflicts and resolving them. 
 - Prioritizing requirements. 

3. **Requirement Specification** 
 - Documenting requirements in Software Requirement Specification (SRS). 
 - Ensuring clarity, completeness, and consistency. 

4. **Requirement Validation** 
 - Checking for errors, ambiguities, and inconsistencies. 
 - Conducting reviews and testing. 

5. **Requirement Management** 
 - Handling changes in requirements. 
 - Maintaining traceability and tracking modifications. 

These tasks ensure that software meets user expectations and business objectives.

### **Q3 (b) Define QFD. Explain the types of requirements defined by QFD.** 
#### **Quality Function Deployment (QFD):** 
Quality Function Deployment (QFD) is a structured approach used in software engineering to translate customer needs into engineering requirements. It ensures that the final software product aligns with customer expectations. 

#### **Types of Requirements Defined by QFD:** 

1. **Normal Requirements:** 
 - Basic features expected by customers. 
 - Example: Login functionality in an application. 

2. **Expected Requirements:** 
 - Features that customers assume are included but may not explicitly state. 
 - Example: An e-commerce website having a search bar. 

3. **Exciting Requirements:** 
 - Innovative features that delight customers. 
 - Example: AI-based personalized recommendations. 

QFD helps prioritize features based on customer needs and business goals.

### **Q1 (a) Define Software Engineering. List and explain the software characteristics that describe the nature of software.** 

#### **Definition of Software Engineering:** 
Software Engineering is a systematic, disciplined, and measurable approach to software development, operation, and maintenance. It applies engineering principles to ensure software reliability and efficiency. 

#### **Characteristics of Software:** 

1. **Software is Developed, Not Manufactured:** 
 - Unlike hardware, software is created through design and coding rather than assembly. 

2. **Software Doesn’t Wear Out:** 
 - Physical components degrade over time, but software does not deteriorate. However, it may become obsolete due to changes in requirements. 

3. **Software is Customizable:** 
 - Software can be modified and upgraded based on user needs. 

4. **Software is Complex:** 
 - Large-scale software systems involve millions of lines of code with intricate interactions. 

5. **Software is Invisible:** 
 - Unlike physical products, software functionality is abstract and cannot be visually inspected. 

6. **Software has No Physical Mass:** 
 - It exists in digital form and doesn’t have material properties like weight or shape. 

7. **Software is Designed with Documentation:** 
 - A well-structured software development process includes requirement documents, design documents, and user manuals. 

---

### **Q1 (b) Explain Evolutionary Process Models, mentioning the types of projects for which they are suitable.** 

#### **Evolutionary Process Models:** 
Evolutionary process models emphasize **incremental** and **iterative** development, where software is built gradually with continuous refinement based on feedback. 

#### **Types of Evolutionary Process Models:** 

1. **Prototyping Model:** 
 - A quick prototype is developed to gather user feedback before building the final system. 
 - **Suitable for:** Projects with unclear or evolving requirements (e.g., UI-heavy applications). 

2. **Incremental Model:** 
 - The software is developed in small, functional increments. 
 - **Suitable for:** Large systems where early delivery of key features is essential (e.g., e-commerce platforms). 

3. **Spiral Model:** 
 - Combines iterative development with risk analysis at each phase. 
 - **Suitable for:** High-risk projects requiring frequent evaluation (e.g., defense and aerospace software). 

4. **Agile Model:** 
 - Focuses on continuous iterations and collaboration with customers. 
 - **Suitable for:** Dynamic projects with frequently changing requirements (e.g., startups, mobile app development).

### **Q2 (a) Explain with a neat diagram the Incremental Model and write its advantages & disadvantages.** 

#### **Incremental Model:** 
- The system is developed in small parts (increments), with each increment adding functionality to the system. 
- Each increment is tested and validated before moving to the next phase.

#### **Advantages:** 
1. Faster delivery of working software. 
2. Easier to test and debug smaller modules.

1. Requires careful planning to divide modules efficiently.

### **Q2 (b) Explain the phases of the Unified Process Model.** 

The **Unified Process Model (UP)** is an iterative and incremental software development process that includes the following phases: 

1. **Inception Phase:** 
 - Define project goals and feasibility. 
 - Identify key stakeholders and high-level requirements. 

2. **Elaboration Phase:** 
 - Perform risk analysis and refine system architecture. 
 - Develop initial prototypes and validate technical feasibility. 

3. **Construction Phase:** 
 - Develop the core functionalities in iterative cycles. 
 - Perform rigorous testing and debugging. 

4. **Transition Phase:** 
 - Deliver the final product to the user. 
 - Provide training, support, and maintenance. 

Each phase ensures controlled development and continuous improvement. 

---

### **Q2 (c) Explain the Concurrent Development Model.** 

#### **Concurrent Development Model:** 
The **Concurrent Development Model** follows a parallel approach where multiple activities are executed simultaneously, rather than in a strict sequence. 

#### **Key Features:** 
- Development tasks (e.g., design, coding, testing) overlap to speed up the process. 
- Uses feedback loops to adjust to changing requirements. 
- Encourages real-time collaboration among teams. 

#### **Example:** 
In a **web application development** project, UI design, database setup, and API development can happen in parallel instead of waiting for each phase to complete sequentially.
