# Q1 (c) Explain the Operations of Kerberos. \[6\]

## Kerberos

Kerberos is a trusted third-party network authentication protocol that provides secure authentication over an insecure network using secret-key cryptography. It prevents unauthorized access and replay attacks.

### Components of Kerberos

1. **Client/User**
2. **Authentication Server (AS)**
3. **Ticket Granting Server (TGS)**
4. **Service Server**
5. **Ticket Granting Ticket (TGT)**

## Working of Kerberos

### 1. User Login and Authentication

The user enters credentials and sends a request to the Authentication Server (AS). The AS verifies the user's identity using information stored in its database.

### 2. Ticket Granting Ticket (TGT)

After successful authentication, the AS sends a Ticket Granting Ticket (TGT) encrypted with the TGS secret key. The client cannot modify this ticket.

### 3. Request to TGS

When the user wants to access a network service, the client sends the TGT to the Ticket Granting Server (TGS) and requests access to the desired service.

### 4. Service Ticket Generation

The TGS verifies the TGT and issues a Service Ticket. This ticket contains session information and is encrypted using the service server's secret key.

### 5. Accessing the Service

The client presents the Service Ticket to the target server. The server validates the ticket and authenticates the user.

### 6. Secure Communication

After successful authentication, both client and server use a shared session key for secure communication.

## Kerberos Authentication Flow

| Step | Action |
|--------|---------|
| 1 | Client → AS : Login Request |
| 2 | AS → Client : TGT |
| 3 | Client → TGS : TGT + Service Request |
| 4 | TGS → Client : Service Ticket |
| 5 | Client → Server : Service Ticket |
| 6 | Server → Client : Access Granted |

## Example

In a university network, a student logs in once and receives a TGT. The same ticket can then be used to access email services, library systems, and academic portals without entering credentials repeatedly.

### Conclusion

Kerberos provides mutual authentication, secure ticket-based access, single sign-on capability, and protection against password interception and replay attacks.

# Q2 (a) Explain the Operation of the MD5 Message Digest Algorithm with a Neat Diagram. \[6\]

## MD5 Message Digest Algorithm

MD5 (Message Digest Algorithm 5) is a cryptographic hash function developed by Ronald Rivest. It accepts a message of any length and produces a fixed 128-bit message digest. The digest acts as a digital fingerprint of the original message.

## Working of MD5

### 1. Padding

The original message is padded so that its length becomes 64 bits less than a multiple of 512 bits. A single '1' bit is added followed by enough '0' bits.

### 2. Append Message Length

A 64-bit representation of the original message length is appended to the padded message.

### 3. Initialize Buffer

Four 32-bit registers are initialized:

- A = 67452301
- B = EFCDAB89
- C = 98BADCFE
- D = 10325476

These registers together form a 128-bit buffer.

### 4. Process Message Blocks

The message is divided into 512-bit blocks. Each block undergoes four rounds of processing, with 16 operations per round.

The four auxiliary functions used are:

- F(B,C,D)
- G(B,C,D)
- H(B,C,D)
- I(B,C,D)

### 5. Generate Digest

After processing all blocks, the contents of A, B, C, and D are concatenated to form the final 128-bit message digest.

## MD5 Block Diagram

```text
 │
 ▼
 Padding
 │
 ▼

 │
 ▼
512-bit Blocks
 │
 ▼

 │
 ▼

 │

```

## Example

Message:

```text
HELLO
```

```text

```

## Conclusion

MD5 generates a fixed-size 128-bit hash value used for integrity verification, password storage, and digital signatures. Any small change in the message produces a completely different digest.

Public Key Cryptography, also called Asymmetric Cryptography, uses two mathematically related keys: a public key and a private key.

- Public Key → Used for encryption
- Private Key → Used for decryption

The public key can be shared openly, while the private key remains secret.

## Key Generation

1. Select two large prime numbers.
2. Calculate their product.
3. Generate a public key.
4. Generate a corresponding private key.
5. Distribute the public key while keeping the private key secret.

## Encryption Process

## Decryption Process


## Example

# Q2 (c) Explain X.509 Authentication Service. \[6\]

## X.509 Authentication Service

X.509 is an international standard that defines the format of digital certificates used in Public Key Infrastructure (PKI). It enables authentication, confidentiality, and integrity in secure communications.

A trusted Certificate Authority (CA) issues digital certificates to verify the identity of users, organizations, and servers.

## X.509 Certificate Structure

An X.509 certificate contains:

| Field | Description |
|---------|-------------|
| Version | Certificate version |
| Serial Number | Unique certificate number |
| Signature Algorithm | Algorithm used by CA |
| Issuer Name | Certificate Authority |
| Subject Name | Certificate owner |
| Public Key | Subject's public key |
| Validity Period | Start and expiry dates |
| Digital Signature | Signature of CA |

## Certificate Chain

A certificate chain establishes trust.

```text
Root CA
 │
Intermediate CA
 │
Server Certificate
```

The receiver verifies each certificate in the chain until reaching the trusted Root CA.

## Certificate Revocation List (CRL)

A CRL is a list published by the CA containing certificates that have been revoked before their expiration date.

Reasons for revocation include:

- Private key compromise
- Change of ownership
- Security violations

Systems check the CRL before trusting a certificate.

## Usage in SSL/TLS

During SSL/TLS handshake:

1. Server sends its X.509 certificate.
2. Client verifies the certificate.
3. Client checks the CA signature and certificate validity.
4. Secure session keys are exchanged.
5. Encrypted communication begins.

## Example

When a user visits an HTTPS website, the browser verifies the server's X.509 certificate issued by a trusted CA before establishing a secure connection.

## Conclusion

X.509 provides a standardized framework for digital certificates, certificate validation, certificate revocation, and secure authentication in SSL/TLS, VPNs, email security, and other PKI-based systems.

# Q3 (a) List and Explain the Components of the IPSec Protocol and the Security Services it Provides. \[6\]

## IPSec (Internet Protocol Security)

IPSec is a suite of protocols used to secure IP communications by providing authentication, integrity, confidentiality, and access control. It operates at the network layer and is widely used in VPNs.

## Components of IPSec

### 1. Authentication Header (AH)

Authentication Header provides authentication, data integrity, and protection against replay attacks.

- Verifies the sender's identity.
- Ensures data has not been modified during transmission.
- Does not provide encryption.

### 2. Encapsulating Security Payload (ESP)

ESP provides confidentiality through encryption and also supports authentication and integrity.

- Encrypts packet payload.
- Protects data from unauthorized access.
- Most commonly used IPSec component.

### 3. Internet Key Exchange (IKE)

IKE is responsible for secure key management.

- Establishes security associations.
- Generates and exchanges cryptographic keys.
- Automates authentication between communicating parties.

### 4. ISAKMP (Internet Security Association and Key Management Protocol)

ISAKMP provides a framework for establishing, negotiating, modifying, and deleting Security Associations.

- Defines procedures for key management.
- Works together with IKE.

### 5. Security Association (SA)

A Security Association is a logical connection between two communicating parties.

It specifies:

- Encryption algorithm
- Authentication algorithm
- Keys used
- Lifetime of the connection

## Security Services Provided by IPSec

| Security Service | Description |
|-----------------|-------------|
| Authentication | Verifies sender identity |
| Data Integrity | Detects modification of data |
| Confidentiality | Encrypts data to prevent disclosure |
| Access Control | Restricts unauthorized access |
| Replay Protection | Prevents duplicate packet attacks |

## Conclusion

IPSec secures IP communication using AH, ESP, IKE, ISAKMP, and Security Associations, providing confidentiality, integrity, authentication, and protection against network attacks.

# Q3 (c) Explain the Working of PGP (Pretty Good Privacy) in Detail. \[6\]

## Pretty Good Privacy (PGP)

PGP is an email security system developed by Phil Zimmermann. It provides confidentiality, authentication, integrity, compression, email compatibility, and message segmentation.

PGP combines symmetric-key cryptography, public-key cryptography, hashing, and compression techniques.

## Working of PGP

### 1. Authentication

The sender first creates a hash (message digest) of the message using a hashing algorithm.

The hash is encrypted using the sender's private key to create a digital signature.

This allows the receiver to verify the sender's identity and message integrity.

### 2. Confidentiality

The original message is encrypted using a randomly generated session key and a symmetric encryption algorithm.

The session key is then encrypted using the receiver's public key.

Only the receiver can recover the session key using their private key.

### 3. Compression

Before transmission, PGP compresses the message.

Benefits:

- Reduces message size.
- Improves transmission efficiency.
- Provides additional security by reducing redundancy.

### 4. Email Compatibility

Many email systems support only ASCII characters.

PGP converts encrypted binary data into ASCII format using Radix-64 encoding so that it can be transmitted through email systems.

### 5. Segmentation

Large messages are divided into smaller segments before transmission.

At the receiver side, all segments are reassembled to reconstruct the original message.

## PGP Process

```text
Message
 │
Hash Function
 │
Digital Signature
 │
Compression
 │
Symmetric Encryption
 │
Session Key Encryption
 │
Radix-64 Encoding
 │
Transmission
```

## Features of PGP

| Feature | Purpose |
|----------|----------|
| Authentication | Verifies sender identity |
| Confidentiality | Protects message content |
| Integrity | Detects message modification |
| Compression | Reduces message size |
| Email Compatibility | Converts data into ASCII format |
| Segmentation | Handles large messages efficiently |

## Conclusion

PGP provides secure email communication by combining digital signatures, encryption, compression, and encoding techniques. It ensures confidentiality, authentication, integrity, and efficient transmission of electronic messages.

# Q5 (a) Explain the Architecture of a Firewall and List its Types. \[6\]

## Firewall

A Firewall is a network security system that monitors and controls incoming and outgoing network traffic based on predefined security rules. It acts as a barrier between a trusted internal network and an untrusted external network such as the Internet.

## Firewall Architecture

A firewall is placed between the internal network and the external network to inspect and filter traffic.

```text
Internal Network
 │
 ▼
 Firewall
 │
 ▼
 Internet
```

### Working of Firewall

1. Incoming and outgoing packets pass through the firewall.
2. The firewall checks packets against security rules.
3. Authorized traffic is allowed.
4. Unauthorized or suspicious traffic is blocked.
5. Logs are maintained for monitoring and auditing.

## Types of Firewall

### 1. Packet Filtering Firewall

This is the simplest type of firewall. It examines packet headers such as source address, destination address, port number, and protocol.

- Operates at Network Layer.
- Allows or blocks packets based on predefined rules.
- Fast but provides limited security.

### 2. Stateful Inspection Firewall

This firewall maintains information about active connections in a state table.

- Monitors ongoing sessions.
- Allows only packets belonging to valid connections.
- More secure than packet filtering.

### 3. Application Gateway Firewall (Proxy Firewall)

Acts as an intermediary between client and server.

- Examines application-layer traffic.
- Hides internal network details.
- Provides high security.

### 4. Circuit-Level Gateway

Monitors TCP handshakes and session establishment.

- Verifies legitimacy of sessions.
- Does not inspect packet contents.
- Operates at Session Layer.

## Comparison of Firewall Types

| Type | Layer | Main Function |
|--------|--------|--------------|
| Packet Filtering | Network | Filters packets based on rules |
| Stateful Inspection | Network/Transport | Tracks active sessions |
| Application Gateway | Application | Inspects application traffic |
| Circuit-Level Gateway | Session | Verifies session establishment |

## Conclusion

Firewalls protect networks by filtering and monitoring traffic. Packet filtering, stateful inspection, application gateways, and circuit-level gateways provide different levels of security depending on organizational requirements.

## IDS vs IPS

IDS (Intrusion Detection System) and IPS (Intrusion Prevention System) are security technologies used to identify and handle malicious activities in a network.

| Parameter | IDS | IPS |
|------------|-----|-----|
| Full Form | Intrusion Detection System | Intrusion Prevention System |
| Primary Function | Detects attacks | Detects and prevents attacks |
| Placement | Monitors network traffic | Placed inline with traffic flow |
| Response | Generates alerts | Blocks malicious traffic |
| Action Type | Passive | Active |
| Impact on Traffic | Does not affect traffic flow | Can stop suspicious packets |
| Objective | Detection and monitoring | Prevention and protection |
| Example Action | Sends warning to administrator | Drops packet or terminates connection |

## Working Difference

An IDS analyzes network activities and notifies administrators when suspicious behavior is detected. However, it does not directly stop the attack.

An IPS not only detects malicious activity but also takes immediate action such as blocking packets, resetting connections, or preventing access from suspicious sources.

## Conclusion

IDS is mainly used for monitoring and detecting threats, whereas IPS provides real-time protection by actively preventing attacks before they can affect the system.

# Q6 (a) List and Explain the Types of Intrusion Detection System (IDS) in Detail. \[6\]

## Intrusion Detection System (IDS)

An Intrusion Detection System (IDS) is a security mechanism that monitors network traffic and system activities to detect unauthorized access, attacks, or policy violations. When suspicious activity is detected, it generates alerts for administrators.

## Types of IDS

### 1. Network-Based IDS (NIDS)

A Network-Based IDS monitors traffic flowing through a network segment.

- Installed at strategic locations in the network.
- Examines packets passing through the network.
- Detects attacks such as DoS, port scanning, and malware propagation.

**Example:** Snort

### 2. Host-Based IDS (HIDS)

A Host-Based IDS is installed on an individual host or device.

- Monitors system logs, files, and processes.
- Detects unauthorized file modifications and suspicious activities.
- Provides detailed information about attacks on a specific system.

**Example:** OSSEC

### 3. Signature-Based IDS

This IDS identifies attacks by comparing activities with a database of known attack signatures.

- Effective against known threats.
- Generates alerts when a matching pattern is found.
- Requires regular signature updates.

**Example:** Antivirus software detecting known malware signatures.

### 4. Anomaly-Based IDS

This IDS establishes a normal behavior profile and identifies deviations from that profile.

- Detects previously unknown attacks.
- Useful for identifying zero-day threats.
- May generate false positives.

**Example:** Detecting unusually high network traffic from a user account.

### 5. Hybrid IDS

A Hybrid IDS combines Signature-Based and Anomaly-Based detection techniques.

- Provides better detection accuracy.
- Detects both known and unknown attacks.
- Widely used in modern security environments.

## Comparison of IDS Types

| Type | Monitoring Area | Strength |
|--------|----------------|----------|
| NIDS | Network Traffic | Detects network attacks |
| HIDS | Individual Host | Detects host-level attacks |
| Signature-Based | Known Patterns | Accurate for known threats |
| Anomaly-Based | Behavioral Changes | Detects unknown attacks |
| Hybrid | Combined Approach | Comprehensive protection |

## Conclusion

Different IDS types focus on different aspects of security. Organizations often deploy Hybrid IDS solutions to achieve comprehensive intrusion detection and improved security.

# Q6 (b) What is Access Control Security Service? Distinguish Between DAC, MAC, RBAC and ABAC with Examples. \[6\]

## Access Control Security Service

Access Control is a security service that regulates who can access system resources and what operations they are permitted to perform. It ensures that only authorized users can access specific data, applications, or services.

The primary objective of access control is to protect confidentiality, integrity, and availability of information.

## Types of Access Control

### 1. Discretionary Access Control (DAC)

In DAC, the owner of a resource decides who can access it.

- Access permissions are controlled by resource owners.
- Flexible and easy to implement.
- Commonly used in operating systems.

**Example:** A file owner grants read or write permissions to another user.

### 2. Mandatory Access Control (MAC)

In MAC, access decisions are made based on security labels and classifications.

- Users cannot change permissions.
- Controlled by system administrators.
- Commonly used in military and government systems.

**Example:** A user with "Secret" clearance cannot access "Top Secret" documents.

### 3. Role-Based Access Control (RBAC)

Access permissions are assigned according to organizational roles.

- Users receive permissions through assigned roles.
- Simplifies administration.
- Widely used in enterprises.

**Example:** HR staff can access employee records, while finance staff can access payroll data.

### 4. Attribute-Based Access Control (ABAC)

Access decisions are based on attributes of users, resources, and environments.

- Provides fine-grained access control.
- Considers multiple factors simultaneously.
- Suitable for dynamic environments.

**Example:** A doctor can access patient records only during working hours and from the hospital network.

## Comparison of DAC, MAC, RBAC and ABAC

| Feature | DAC | MAC | RBAC | ABAC |
|-----------|-----|-----|------|------|
| Control By | Resource Owner | System Authority | User Role | Attributes |
| Flexibility | High | Low | Medium | Very High |
| Security Level | Moderate | Very High | High | Very High |
| Permission Assignment | Individual Users | Security Labels | Roles | Attributes & Policies |
| Example | File Sharing | Military Systems | Company Departments | Cloud Security |

## Conclusion

DAC, MAC, RBAC, and ABAC provide different approaches to access control. Modern organizations often use RBAC and ABAC because they offer efficient management and stronger security.

# Q6 (c) Explain the Following Attack Types and Countermeasures. \[5\]

## (i) Dictionary Attack

A Dictionary Attack is a password-cracking technique in which an attacker tries a predefined list of commonly used words, phrases, and passwords to gain unauthorized access.

### Countermeasures

- Use strong passwords.
- Avoid common dictionary words.
- Implement account lockout policies.
- Enable Multi-Factor Authentication (MFA).

### Example

Trying passwords such as *admin123*, *password*, or *welcome123* from a prepared dictionary file.

---

## (ii) Social Engineering Attack

A Social Engineering Attack manipulates people into revealing confidential information or performing actions that compromise security.

Attackers exploit human trust rather than technical vulnerabilities.

### Countermeasures

- Conduct security awareness training.
- Verify identities before sharing information.
- Avoid clicking suspicious links.
- Follow organizational security policies.

### Example

An attacker pretending to be a bank representative and asking for account credentials.

---

## (iii) Brute Force Attack

A Brute Force Attack attempts every possible password combination until the correct one is found.

This method relies on computational power and repeated login attempts.

### Countermeasures

- Use long and complex passwords.
- Implement CAPTCHA.
- Enable account lockout after multiple failed attempts.
- Use Multi-Factor Authentication.

### Example

Automated software attempting thousands of password combinations against a login page.

## Conclusion

Dictionary attacks, social engineering attacks, and brute force attacks are common methods used by attackers to gain unauthorized access. Strong passwords, user awareness, account protection mechanisms, and multi-factor authentication are effective measures to reduce these threats.

- Sending threatening emails and messages.
- Creating fake social media accounts.
- Posting false information about the victim.
- Monitoring online activities.
- Installing spyware or malware.
